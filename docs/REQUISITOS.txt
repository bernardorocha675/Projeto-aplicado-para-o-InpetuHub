Quero que você desenvolva um MVP completo e funcional de um sistema web para o InPETU Hub.

Antes de começar a programar, leia TODO este prompt e planeje a arquitetura, o banco de dados, as páginas e os fluxos. Não simplifique requisitos sem necessidade e não invente funcionalidades que não foram solicitadas.

============================================================
1. CONTEXTO DO PROJETO
============================================================

Somos estudantes desenvolvendo um projeto aplicado para o InPETU Hub.

O projeto terá duas interfaces integradas:

1. SITE PÚBLICO / AGENDA
   - utilizado por empreendedores, empresas e instituições;
   - permite consultar a agenda;
   - consultar disponibilidade;
   - selecionar data e horário;
   - selecionar espaço;
   - solicitar uma reserva.

2. SISTEMA INTERNO / CRM
   - utilizado pelos colaboradores do InPETU Hub;
   - protegido por login;
   - recebe as solicitações realizadas pelo site público;
   - permite aprovar, recusar ou alterar uma reserva;
   - permite consultar empreendedores;
   - permite visualizar histórico;
   - permite consultar reservas;
   - mantém o CRM integrado às reservas.

As duas interfaces devem usar o MESMO backend e o MESMO banco de dados.

8. REGRAS DE COTA
============================================================

Implementar:

1. Para utilizar a cota, a solicitação deve ser realizada com pelo menos 15 dias de antecedência.

2. Enquanto houver saldo na cota mensal, as solicitações elegíveis utilizam a cota por ordem de chegada.

3. Reservas PENDENTES devem reservar provisoriamente as horas da cota para impedir concorrência.

4. Se uma reserva pendente for recusada/cancelada sem penalidade, devolver as horas reservadas.

5. Depois de atingir o teto mensal, novas reservas continuam possíveis, porém sem os descontos da cota.

6. Horas não utilizadas não acumulam para o próximo mês.

7. Cancelamento/desistência:
   - comunicado com 30 dias ou mais de antecedência: sem penalidade;
   - comunicado com menos de 30 dias, sem motivo de força maior:
     descontar da cota o dobro das horas reservadas.

Exemplo:
reserva de 4 horas cancelada fora do prazo:
penalidade = 8 horas.

8. Caso a cota atual não seja suficiente para a penalidade, registrar saldo devedor para os meses seguintes.

9. Excepcionalidades podem ser decididas pelo gestor.

============================================================
11. REGRA DO SINAL
============================================================

Toda reserva de sala deve possuir sinal.

Dia comum:
- sinal = 30% do valor final da reserva.

Domingo OU feriado:
- sinal = 60% do valor final da reserva.

Exemplo:

valor final = R$ 1.600

dia comum:
sinal = R$ 480

domingo/feriado:
sinal = R$ 960

O cálculo deve acontecer depois de aplicar taxação/descontos.

Fluxo:

valor base
-> aplicar regra da persona
-> calcular valor final
-> verificar data
-> domingo ou feriado?
-> 30% ou 60%
-> calcular valor do sinal
-> calcular restante

Feriados devem ser consultados na tabela FERIADO.

Não hardcodar feriados dentro do Java.
